# 微信小游戏广告接入与验收

本项目 AppID：`wxc19585dea4453b6b`。当前真实广告关闭，仅预留可配置的激励视频接口与两种奖励。100 关为规划，当前可玩关卡为 20 关。

## 推荐位置

- 前 10 关无广告，先验证玩法与故事吸引力。
- 第 11 关起，每关一次免费寻路；之后玩家主动点“广告寻路”，完整观看后标出一条可移动龙。广告不可用时保留免费寻路作为降级。
- 失败弹窗中：“看广告·保留盘面再试一次”，每局最多一次，获得一次机会；“重新挑战”始终免费。
- 不通过故意无解或突增难度逼看广告，不将广告放在“下一关”按钮上，不用广告解锁主线。不默认开启跳关、横幅或插屏。
- 后续用关卡失败率、提示使用率、看广告后继续游玩的比例和次日留存判断调整。连续多次失败先给更明确的免费引导；广告跳关仅在实测需要时另行设计，且不得冒充正常通关。

## 你在微信后台操作

1. 浏览器打开 https://mp.weixin.qq.com/ ，登录这个小游戏的管理员账号，确认 AppID 与上面相同。
2. 在左侧查找“流量主”（常见于“推广”或“广告与服务”相关菜单）。不要选“广告主”：广告主用于你花钱购买曝光，流量主用于展示广告变现。
3. 如未开通，点击申请，按当前后台实际提示完成小游戏发布、主体/身份、资质与结算资料等条件。不要按网上某个固定用户数或固定证件清单判断；资格、审核材料和可用广告形式以此账号后台为准。仅能扫码体验并不代表广告变现资格已获批。
4. 开通后进入广告管理/广告位管理，创建“激励视频广告”。先创建两个用途清楚的广告位，名称可用“箭头出逃-额外寻路”“箭头出逃-失败续关”。如后台仅允许一个，可先共用一个 ID，代码支持按用途发不同奖励。
5. 从广告位详情或“获取代码”复制 `adunit-...`。不要填 AppID，不需要提供 AppSecret、登录 token 或密码。
6. 把广告位 ID 发给我，或自行填写 `config/ads.json` 的 `rewarded_hint_id` 与 `rewarded_continue_id`，把 `enabled` 改为 `true`。保留 `ad_free_levels: 10` 为正式建议值。
7. 真机验收时可临时将 `ad_free_levels` 改为 `0`，重新运行工作区的 `outputs/export-arrow-wechat.ps1` 打包。导入原 `outputs/wechat-arrow-escape` 目录，编译并预览扫码。不能只修改已导出目录，因为配置已打进 Godot 资源包。
8. 测试完成后恢复 `ad_free_levels: 10`，再次打包，再按微信后台要求上传、审核和发布。实际广告位能否在预览/体验版本展示以后台状态、微信环境与返回错误为准；不要以模拟器表现代替真机验收。

## 必测的五件事

- 一次免费寻路后，按钮变成“广告寻路”，主动点击才播放。
- 完整观看只获得一次对应奖励，不重复加机会。
- 中途关闭、广告没填充、加载失败：不发观看奖励、不扣进度，仍可免费重开。
- 续关保留已经移走的龙，每局最多续一次，重开开始新局。
- 广告期间不能重复点击或切换关卡，回调不能把奖励发给另一局。

## 当前代码流程

`main.gd` 确定入口与奖励 → `game_ads.gd` 校验配置、场景与待处理请求 → 既有 `MiniGameSDK` 调用微信 `createRewardedVideoAd` → SDK 在关闭回调检查 `res.isEnded === true` → 清理监听并一次性回传 → 游戏发奖。已加上错误回调与重复回调保护。
